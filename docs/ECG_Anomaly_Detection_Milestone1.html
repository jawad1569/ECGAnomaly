Dataset

PTB-XL: real clinical ECGs with expert labels

21,388
labelled recordings used (NORM 9,246 · MI 4,187 · STTC 3,345 · CD 3,322 · HYP 1,288)
12 leads
10 seconds each, 1,000 samples per lead at 100 Hz
5 classes
cardiologist-labelled diagnostic superclasses
  • Label = the diagnostic superclass with the highest likelihood in the PTB-XL annotations.
  • Split = the official PTB-XL folds: folds 1–9 train, fold 10 held-out test (2,158 ECGs), so no patient leaks across the split.
Source: PTB-XL, PhysioNet (Wagner et al., 2020)
MI = myocardial infarction, STTC = ST/T change, CD = conduction disturbance, HYP = hypertrophy. Classes are unequal, so we score macro-F1 rather than accuracy alone.
Data preparation

Validate every signal, then extract 467 features

Validation validate_signal()

  • Shape must be (time, 12).
  • At least 100 samples.
  • No NaN or infinite values.
  • Amplitude within ±50 mV.

Same function in training and in the API, which answers 400 on bad input.

Features features.py

  • Per lead: percentiles, skew, kurtosis, slope, zero-crossings, 5 frequency-band powers.
  • Heartbeat: heart rate, RR variability, median-beat shape of every lead.
  • Between leads: correlations with II and V1.

Up from 9 basic statistics per lead (108 features).

ECG Anomaly Detection
The first version used only 9 summary statistics per lead and hit about 52% accuracy: it could not see heartbeat shape or heart rate. The richer features are what moved the score most.
AutoML integration

FLAML picks the model and tunes it for us

  • Search space: LightGBM, XGBoost, ExtraTrees, RandomForest.
  • Objective: macro-F1, 3-fold cross-validation on the training folds.
  • Budget: time-boxed, set by AUTOML_TIME_BUDGET.
  • One child MLflow run per family, then the full search as the parent run.

Experiment tracking

Every run is logged; a worse model never goes live

Logged per run

Estimator, config, time budget, data sizes, accuracy, macro-F1, F1 abnormal.

Registry

Winner registered as ecg_model_v1 with its class names; the API loads the latest version.

Only if better

A retrained model is registered only if its macro-F1 is at least the best registered. We saw this gate reject a weaker run.
